From incident to your decision

Most problems are fixed quietly. Anything risky waits for your Accept or Reject, with a reason.
Paper trading only · no real money

1Something breaks

  • Engine: no prices for 10 min, 3 tick errors in a row, git push failing 15 min
  • Workflow run failed, or tests fail on main
  • Watchdog (every 10 min): engine not running, value near the floor, corrupted state, guidance older than 3 h

2Alert policy (plain code, no AI)

Fingerprint = workflow + step + error type. The same problem is one incident, not ten.

Claude is woken at most 6 times a day. Extra alerts wait and join the next email.

Alerts within 15 min of a HIGH share its email.

HIGH: engine stopped, within ₹100 of the floor, corrupted state, tests failing on main
MEDIUM: data source down, failed run, stale guidance
LOW: one-off fetch error, slow run

3Incident routine

Haiku summarises the payload and logs in 15 lines

Sonnet triages:

  • Trivial: restart, re-run, restore a file, known holiday. Sonnet fixes it
  • Standard: a data source needs a fallback, a test fix. A Sonnet helper writes it
  • Complex: unknown cause, trading logic

Opus helper writes the fix or pull request

Safe fix: done on main

Only after tests pass. Re-start the engine, restore state from backup, add a missing NSE holiday, add a tested data fallback, re-run a failed job.

Anything else: a pull request

Trading rules, config/params.yaml, the rulebook, floor logic, permissions, secrets. Branch claude/fix-…. Never merged without you.

4You get an email

  • HIGH: at once, plus a GitHub issue "[HIGH] …"
  • MEDIUM: only if it needs your approval or the fix failed
  • LOW: never. It shows under "Fixed today" in the daily email

Subject starts "Metals Daybook". Sent only to your one address.

5Daybook Inbox

A claude.ai page with one item per decision, and two buttons:

AcceptReject

Reject has a reason box. Either button wakes the incident routine within a minute.

Daily report items say "Looks right".

Accept

  • Checks the pull request is the one in the incident record, open, and CI is green
  • Squash-merges it
  • Email "Applied"; item turns resolved

Reject, with a reason

  • Opus revises the same branch using your reason (it can never override the safety rules)
  • Email "Revised"; a new item to accept or reject
  • After 3 revisions: "Needs a human look"
  • Reason saved as a lesson candidate

Hourly reminders until you ACK

A HIGH alert is re-sent every hour (24 at most) until you acknowledge it by:

  • replying ACK, OK or SEEN in the same email thread
  • commenting ack on the GitHub issue, or closing it
  • the button in the email

Safe mode

Turns on after more than 5 different incidents in a day, or a HIGH not fixed in 30 minutes.

  • No new buys
  • Exits, stops and the floor keep working
  • Clears after a verified fix, or a healthy pre-market check

Why it stays cheap

  • Repeats never wake Claude twice
  • Reminders and checks are free GitHub jobs
  • An email reply can only ACK, never approve code
  • Logs, headlines and payloads are treated as untrusted text
